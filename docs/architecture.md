## Data Flow

1. **`data/assets.csv`** — 100 synthetic fleet assets generated by `src/data/generate_dataset.py` (fixed seed=42, reproducible).
2. **Risk Engine** — loads and validates the CSV, imputes missing values, engineers features, fits a logistic regression blended with a domain heuristic score, and produces per-asset health scores, failure probabilities, risk levels, readiness classifications, explainable risk factors, and recommended actions.
3. **FastAPI REST API** — a thin wrapper (`src/api/main.py`) that exposes the risk engine Python functions as HTTP endpoints at `http://localhost:8000`. Does not reimplement any scoring logic.
4. **Streamlit Dashboard** — connects to the FastAPI backend via `src/dashboard/api_client.py` and presents fleet KPIs, charts, the maintenance priority queue, and per-asset detail views at `http://localhost:8501`.
5. **MCP Server** — `src/mcp/server.py` exposes five MCP tools that call the risk engine Python functions directly. Runs over stdio transport via `run_mcp_server.py`.
6. **IBM Bob** — reads `.bob/mcp.json` to discover the `missionguard-mcp` server, spawns the MCP process, and routes natural-language queries to the appropriate tools. IBM Bob is the conversational interface; all numerical analysis is performed by the MissionGuard risk engine.

## IBM Bob ↔ MCP ↔ Risk Engine

```
User natural-language prompt
        ↓
IBM Bob (conversational AI)
        ↓  reads .bob/mcp.json → spawns run_mcp_server.py
MissionGuard MCP Server  (src/mcp/server.py  ·  stdio transport)
        ↓  calls Python functions in src/services/risk_engine.py
Risk Engine  (logistic regression + domain heuristic blend)
        ↓  reads
data/assets.csv  (100 synthetic assets)
        ↓  structured result returned up the stack
IBM Bob formats and presents the answer to the user
```

**Key separation of concerns:**

- IBM Bob is the *conversational* layer — it interprets natural language and decides which MCP tool to call.
- The MCP server is the *interface* layer — it translates tool calls into risk engine function calls.
- The risk engine is the *analysis* layer — it performs all numerical risk scoring, readiness classification, and explainability.

IBM Bob does not perform numerical risk calculations. The MCP server does not reimplement any risk logic. All scoring is done in `src/services/risk_engine.py` and its dependencies.

## MCP Tools

Five tools are registered in `src/mcp/server.py`:

| Tool | Parameters | Returns |
|---|---|---|
| `list_assets` | `readiness_filter`, `risk_filter`, `asset_type_filter` (all optional) | Filtered list of assets with risk and readiness data |
| `get_asset_readiness` | `asset_id` (required) | Readiness status, health score, risk factors, recommended action |
| `get_asset_failure_risk` | `asset_id` (required) | Failure probability, risk level, risk factors, recommended action |
| `get_asset_maintenance` | `asset_id` (required) | Priority score (0–100), fleet rank, priority reasons, recommended action |
| `get_fleet_summary` | none | Fleet counts, readiness/risk percentages, top-10 priority queue |

## REST API Endpoints

Served at `http://localhost:8000` by `src/api/main.py`:

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Service health check |
| GET | `/assets` | All 100 assets with risk and readiness |
| GET | `/assets/{id}/status` | Readiness status for one asset |
| GET | `/assets/{id}/risk` | Failure risk analysis for one asset |
| GET | `/assets/{id}/priority` | Maintenance priority for one asset |

Auto-generated API documentation: `http://localhost:8000/docs` (Swagger) · `http://localhost:8000/redoc`

## Security Considerations

- No real military or operational telemetry is used.
- No cloud credentials are required for local development.
- `.env` is gitignored; `src/.env.example` documents variable names only.
- `WATSONX_API_KEY`, `WATSONX_PROJECT_ID`, `WATSONX_URL` are reserved for future
  watsonx.ai integration and are not required for the local demo.
- No authentication layer — suitable for local demo, not production deployment.

---

## Scalability Notes

The risk engine scores ~100 rows in-process on each load (< 1 second on modern hardware).
The FastAPI and MCP layers are thin wrappers and can be horizontally scaled independently.
The dashboard requires the FastAPI backend to be running; it degrades gracefully if the
backend is offline.
